## Full changelog

### Reminders

- **Reminder notifications work in release builds.** R8 resource shrinking
  removed the small-icon drawable because it is referenced only by name from
  Dart, so `initialize()` failed and no notification was ever shown
  (`434603cf`, and the older `4bbabc28`). The drawable is now kept with
  `tools:keep` in `android/app/src/main/res/raw/keep.xml`; guard test in
  `test/android_manifest_test.dart`.
  Shipped in `1.0.6+7`, first *public* build here.
- **A slow backend no longer kills the reminders screen.** A failing
  people-lookup threw out of `Either.fold`'s async callback and became an
  unhandled error (`8dc90b97`); the use cases now return a `Failure` and the
  screen shows its retryable error state. Same fix in notes.

### Account & invites

- **Notification settings open again.** The reminder notification service was
  registered only as `IReminderNotificationService`, while the route resolves
  it as the core `NotificationSender`; GetIt threw *not registered* and the
  route then disposed a `null` provider (`6ec637b0`, `2c097c74`). The same
  singleton is now registered under both types, pinned by a locator test.
- **Invite failures are readable.** A failed `resend-email-v1` call surfaced as
  a raw gateway error (`fd17dfd5`); every edge-function throw now maps to the
  localized "couldn't send" message while the stack trace still reaches
  Crashlytics.

### UI

- **Tap ripples are back.** Card colours moved onto a `Material`, so Android
  ink splashes are visible on the reminder editor notification card, the
  account settings sections and the notification settings cards
  (`9f6fe1d`). The previous `DecoratedBox` also hit a Flutter 3.47 assertion.
- **Flutter 3.47.8 / Dart 3.13.7**, with refreshed golden baselines
  (`ca6b71f`, `212aa3d`).

### Under the hood

- **Billing fails closed.** An invalid RevenueCat key disables billing for the
  session instead of emitting a handled non-fatal on every entitlement and
  offering lookup (`704f61c6`).
- **AGP 9.0.1 + Gradle 9.1.0**, which turns on optimized resource shrinking
  inside R8 (`28eaa2a`); `isMinifyEnabled`/`isShrinkResources` are now explicit
  and `android/app/proguard-rules.pro` exists for app-level keep rules.
- **BakeAgent** runs Bakehub tasks inside the dev-container image, one PR per
  task, gated on analyze + test (`25be509`).
- Two `unawaited_return_in_try_block` warnings fixed in the usage-limit use
  cases (`fa8dbf6`).

## Notes

- **Billing is disabled in this build unless the release workflow passes the
  RevenueCat key.** `build_aab_release.yml` defines only `APP_FLAVOR`,
  `SUPABASE_URL` and `SUPABASE_PUBLISHABLE_KEY`; `REVENUECAT_GOOGLE_API_KEY` is
  optional in `AppConfig`, so `SubscriptionService.initialize` skips
  configuration and `isBillingAvailable` stays `false` — every user is treated
  as free and no purchase can complete. Add
  `--dart-define=REVENUECAT_GOOGLE_API_KEY=${{ secrets.REVENUECAT_GOOGLE_API_KEY }}`
  before shipping a build that should sell subscriptions. `build_apk.yml` has
  the same gap.
- Version code `8` > `7` (internal) > `6` (production), so the upload is
  accepted without a manual bump.
- The release workflow uploads to the `internal` track with
  `status: completed`; production promotion is manual in the Play Console.
- `sdk`/`targetSdk` come from the Flutter Gradle plugin (`flutter.compileSdkVersion`);
  no app-level override in this build.
