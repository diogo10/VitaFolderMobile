## Full changelog

### Sign in with Apple

- **Native Apple ID sign-in** on the sign-in (`/account`) and sign-up
  (`/sign-up`) screens, next to Google Sign-In (`cae32d6`).
  - Fresh nonce per attempt, SHA-256 hashed for Apple, sent back with the
    identity token so Supabase verifies the `nonce` claim and rejects replayed
    tokens (`signInWithIdToken`, provider `apple`).
  - Apple only returns the user's name on the first authorization; it is
    stored in the user metadata and the `profiles` row, best effort, never
    failing the sign-in.
  - Cancelling stays a neutral state, not an error.
  - The button is platform-gated: it only renders where native Apple sign-in
    exists, so it never dead-ends on Android.
  - Entitlement and Xcode capability declared for the Runner target.
- **`show_apple_login` Remote Config flag** to show or hide the button without
  a release (`46a3a63`). Default `false`; a failed fetch keeps the default, so
  the button can never appear by accident. Read at startup and passed to the
  UI as a plain boolean, keeping Firebase and GetIt out of presentation.

### Stability

- **Emitting into a closed cubit no longer crashes.** A route-scoped cubit can
  be closed while an async flow is still in flight (native Google/Apple sheet,
  store call, backend request); `Cubit.emit` then threw a `Bad state` and the
  app died (`04df8a6a`). Every emit after an `await` now goes through
  `_emitIfOpen` across sign-up, manage profile, notification settings, invite
  people, family settings, paywall and create reminder. Guards:
  `test/cubit_emit_guard_test.dart` (source scan) and a behavioural test that
  closes the cubit mid-flight (`062b902`).
- **Note editor list button fixed at offset 0.** The current-line lookup used
  `lastIndexOf('\n', start - 1)`, which receives `-1` when the cursor sits at
  the very start of the content and throws `RangeError` (`978e9b8f`). Now
  guarded by `start <= 0`; regression test in
  `packages/house_mira_notes/test/presentation/notes_view_test.dart`.

### Docs & tooling

- Crash-triage skill (`.agents/skills/firebase-crashlytics/`), `.firebaserc`
  pinning the active Firebase project, and the real MCP authentication
  (Application Default Credentials) documented in `README.md`.

## Notes

- The Apple button is only visible when `show_apple_login` is `true` in
  Firebase Remote Config **and** the platform supports native Apple sign-in.
  If the flag was left at its default `false`, the first line of the Play text
  above describes something users cannot see.
- Both 1.0.5 issues that are still listed as open in Crashlytics are fixed by
  the 1.0.6 code but only stop reporting once a build carrying it reaches
  users — that is 1.0.7, since 1.0.6 stayed on the internal track.
